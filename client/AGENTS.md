# DiveVision client agent notes

Expo app (React Native + TypeScript, Expo Router, web first). `README.md` has the screens, data
flows, configuration and commands; the repo-root `AGENTS.md` has the backend/RLS rules it
depends on.

## Expo changes fast — check the docs for this SDK

Read the `expo` major version in `package.json`, then the matching docs
(`https://docs.expo.dev/versions/v<major>.0.0/`, or `https://docs.expo.dev/llms.txt`) before
touching an Expo, EAS or React Native API. Add packages with `npx expo install <pkg>` so
versions match the SDK. The lint config includes the React Compiler rules (no ref reads or
synchronous `setState` in render/effects).

## Rules

- Routes live in `src/app/`; everything else (components, hooks, data access) lives outside it.
- Reads go to Supabase with an explicit `user_id` filter (`src/lib/photos.ts`); writes go
  through the generated API client (`src/api/`). Never add a client-side Supabase write.
- Only public config (`EXPO_PUBLIC_*`) may reach the client; never the service-role key.
- `src/api/schema.d.ts` and `openapi.json` are generated (`npm run api:update`); CI fails if
  they are stale.
- Tests run offline: fake Supabase with `src/test-utils/fakeSupabase.ts`, mock `@/lib/api`.
- `ios/` and `android/` are generated by `npx expo prebuild` (git-ignored); configure native
  behaviour in `app.json`.
